- **Where:** `supabase/migrations/017_baseline_amendment.sql:725` creates `core.resolve_quotation_sst()`.

  (`$EV/out/rv6_rb017__test_007_*.log:18-19`). After a 017 rollback, no quotation can be created
  or edited until someone drops the trigger by hand or re-applies 017.
- **Why the existing evidence missed it:** fix-014's "017→011→017 round trip, empty catalog diff"
  is true, and I reproduced it (`$EV/catdiff-rv6_fwd.txt`, 0 lines). But re-applying 017 runs
  `CREATE OR REPLACE` over the orphan, so A = B hides it. It shows up only when you compare each

  and no pin ever runs at a rolled-back floor.

  and using it leaves the core commercial write broken. The failure is loud, not silent.

  `DROP TRIGGER IF EXISTS trg_quotations_resolve_sst ON core.quotations;` and
  `DROP FUNCTION IF EXISTS core.resolve_quotation_sst();`, plus a post-rollback assertion that
  neither survives. Better still, run `test_007` at the 016 floor in the rollback harness.
- **Other rollbacks are clean.** Per-step diffs against fresh builds show 012, 014, 015 and 016
  add nothing beyond this orphan and the two carried residues (§4).
