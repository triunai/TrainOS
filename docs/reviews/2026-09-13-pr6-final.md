## Appendix · Thermonuclear notes on 014–017 (non-blocking)

- **File size.** 014 (1788 lines) and 017 (1639) are both new files over 1k, with pins at 1362
  and 981. 017 is nine unrelated amendments (grants, JSONB rulings, precision, SST, PDPA, HRD
  Corp, accreditation, retrieval) in one transaction. That is why the SST rollback half was easy
  to miss among the other eight. Splitting future baselines one ruling per file would have
  isolated NEW-1.
- **Rollbacks are hand-enumerated, not manifest-driven.** 014 drops policies from a
  `migration:014` stamp. 017 lists objects by hand and missed one. A single "objects created by
  017" query (from `pg_depend` or a comment stamp, the way 014 does policies), asserted empty
  after rollback, removes this whole class of defect.
- **Hand-copied lists.** The gated nine-table set still appears in 014 §2/§4b and in the pin
  (prior thermo finding). It has not drifted today, but nothing keeps the copies in sync.
- **Stale DROP comments.** `011:3432` and `014:1326` `DROP FUNCTION IF EXISTS … (jsonb, …)`
  drop the new signature, not the old `uuid[]` one the comments say they remove. On a fresh
  project this changes nothing. On a database carrying the pre-`062e5e2` 011 it would leave the
  bypass overload in place, though 011's in-place amendment cannot be re-applied there anyway,
  and 011 verify's function count (28) would abort. The comment should match the statement.
- **Rollback ordering guards are uneven.** 014 and 016 refuse while 017 is applied; 015 does not.
