▸Annotation & handoff · M20-S20
Purpose
Decide which model runs which action, what it falls back to, when it may run and what it may cost.
Primary user
System Admin; MD approves cap raises.
Components used
Page header, MetricStrip, warning banner, data table with hour strip and budget bar, assignment matrix, tier chip, jury chip.
Data contract
ModelTier{key,model,provider,routing:"THROUGHPUT"|"PRICE"|"FIXED",fallbackChain[],cacheStrategy,maxOutputTokens,allowedHours[],monthlyCap:Money,spend:Money,status} · ActionRouting{actionType,tierKey,escalationLadder[],juryEnabled,juryQuorum}
Actions & policy gates
Apply to future runs (primary — never retroactive), edit a tier, raise a cap (MD approval), open incidents.
States rendered
One tier degraded with the live fallback named, one paused by cap, two unsaved matrix edits.
AI & approval behaviour
This is the control surface for model selection. Every downstream ✦ badge reports the tier chosen here.
Wired to
Provider keys → M20-S21 · Usage → M20-S16 · Fallbacks fired → M18-S04 filtered runs.
Assumptions
Peak bands 09–12 and 14–18 MYT reflect DeepSeek pricing; batch-eligible tiers are restricted to off-peak. Changes apply to future runs only, never to in-flight ones.

▸Annotation & handoff · M20-S21
Purpose
Hold the customer’s own provider keys, prove they work, and show what each one is spending and serving.
Primary user
System Admin only; Finance sees spend through Usage.
Components used
Page header, MetricStrip, danger banner, provider cards with masked key, tier chips, budget bar, dashed empty state.
Data contract
ProviderKey{id,provider,status,maskedKey,scopeTiers[],spendMonth:Money,cap:Money,rotationDate,billingOwner:"CLIENT"|"PASS_THROUGH",region,lastTestedAt,addedBy,rotatedBy}
Actions & policy gates
Add provider key (primary, opens drawer: provider, key, label, scope, cap, billing owner, residency note), Test connection, Replace, Rotate. Keys are write-only — reveal is hold-to-show and audited.
States rendered
One invalid key with the live fallback named, one at 90% of cap, one expiring, one first-run empty state.
AI & approval behaviour
No AI on this screen; it is the plumbing every AI surface depends on.
Wired to
Tier chips → M20-S20 · Spend → M20-S16 · Audit → audit log.
Assumptions
Keys are stored encrypted and never returned in full by the API; residency is shown per provider because PDPA requires the customer to make that call knowingly.
